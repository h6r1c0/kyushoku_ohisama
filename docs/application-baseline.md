# アプリの現行仕様と参照先

この文書は開発担当の道案内。数式や現在の初期人数、料理データの複製ではない。変更前に最新のコード、保存データの意味、テスト、利用者が確定した仕様を照合する。[作業原則](../AGENTS.md)が入口、[テストの実行方法](../tests/README.md)が検証手順。

## 実装の所在

| 対象 | 現行の確認先 | 保護する意味 |
| --- | --- | --- |
| 人数、食材、必要量、乾物、切り分け、設定とヘルプ | index.html、tests/regression.cjs | 0～5歳・学童・大人の人数と、0歳・1～2歳・3～5歳・学童・大人の1人量区分を混同しない。0歳児の人数と喫食、学童の利用有無、基本人数と当日人数を別に扱う。食材別の単位・特例・端数・余り・補足を保つ。 |
| 保存・復元・移行 | index.html と既存の回帰テスト | 保存済みの0、空欄、未確認、未設定、削除、初期値の意味を保つ。部分的な異常値で別の正常な設定を壊さない。新しい既定値で過去の選択を上書きしない。 |
| 検索データの接続 | menu-search-config.js、menu-search.js | 公開するのは配信用の必要最小限のCSV。台帳正本や原本の共有設定を変更しない。検索タブを開いたときに更新を確認し、量計算中には検索データを取得しない。 |
| 検索の分類・正規化・索引・並び替え・前年同時期 | menu-search-core.js、tests/menu-search.cjs | 台帳原記録を書き換えず、対象6区分、除外、表記揺れ、食材補助、料理統合、提供日・同日献立を扱う。推測の材料を実績として確定しない。 |
| 検索表示と端末キャッシュ | menu-search.js、tests/menu-mobile.cjs | 保存済みCSVを先に使い、裏で更新確認する。差分がなければ不要な再構築を避け、破損や容量超過、通信失敗を扱う。配信遅延を考慮する。 |
| 実画面と公開 | tests/mobile.cjs、.github/workflows/meal-regression.yml、tests/README.md | 320・375・768pxを含む画面と操作を検証する。公開を求められたらPagesの実物とActions結果を確認する。 |

乾物、切り分け、液量・配合などの具体的な式と入力条件はコード・テスト・ヘルプを根拠にする。未確定の型寸法や配合を推測で仕様化しない。食材の1人量や年齢条件を変更するときは、人数変更時の再計算、食事／おやつの切替、途中表示、保存・再読込を影響に応じて確認する。

検索は料理名・括弧内の材料を探し、カテゴリー、並び替え、詳細、提供日、同日の献立、前年同時期を使う。原記録と一覧上の代表表示を区別する。CSVは台帳「検索配信用」からの派生であり、正本の確認状態や除外情報を失わせてはならない。配信の現行抽出条件はシート内の式と運用基準を確認する。

## 変更の判断

短い依頼は、現象→正本と現行動作→原因の切り分け→必要な差分→影響先の検証の順に扱う。「数字が見にくい」なら関連する数値・単位と操作画面を見渡すが、全画面を再設計しない。「検索が遅い」なら取得、キャッシュ、更新確認、索引と描画を分けて調べる。発注・早見表・掲示物は給食改善の対象だが、アプリ、シート、印刷、手順などを現場負担で比較し、資料のない詳細を先に決めない。

実績や献立表の項目別正本・転記・評価・印刷ルールは[実績台帳「進捗と抽出方針」](https://docs.google.com/spreadsheets/d/1PU0VKt9t4Wn7DeiW3WP9BfbjVmF2Bhy0LsDxZv16nP4/edit#gid=921914852)と[月間献立表の対象月・原本](https://docs.google.com/spreadsheets/d/17gWK4n7WphIBbYB9dOqxVQ_gRI9KX9lPluEyeKIWC7E/edit)へ戻る。評価コメントと○は献立表側で守る。
